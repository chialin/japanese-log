# 用 Native Camp 十分鐘自由會話，把學過的文法講出來

## 1. 執行摘要

Scarlett 每天上一堂 Native Camp 的十分鐘自由會話，課前也會準備一點，但上課時常常卡在兩個地方：聽不懂老師在問什麼，以及心裡知道想說什麼、卻組不出日文句子。這份研究整理第二語言習得（SLA）領域對「學了文法卻講不出來」的解釋與練習方法，最後落成一套課前、課中、課後各十到十五分鐘的流程，並提出兩個可以接回這個 repo 的方向。

研究得到三個主要結論：

- **「懂文法」跟「講得出來」是兩種不同的知識。** 技能習得理論（Skill Acquisition Theory）把文法規則叫做陳述性知識，要靠大量「有目的、有系統」的練習，才會變成講話時不用想就拿得出來的程序性知識。目前這個 log 的課程主要在建陳述性知識，自由會話正好是補另一半的地方，但光上課不夠，課前課後的設計才是關鍵。
- **「組不出句子」可以靠事前準備加上重複講同一個話題來改善。** 研究顯示事前規劃（pre-task planning）和重複同一個任務（task repetition）都能提升流暢度，而且效果在重複幾次之後就會趨緩，所以「同一個話題講三次左右」是合理的節奏。把常用的整塊說法（formulaic sequences，像「〜たことがあります」「〜と思います」）背成一個單位，也被證實跟講話流暢度有關。
- **「聽不懂」有一半要靠會話策略解決，不只是聽力。** 研究把「請對方重講、確認意思、重複對方的關鍵字」列為正式的溝通策略，而且事先教過這些策略的學習者，實際對話時真的會用。課後聽自己的錄音、把自己講的話寫下來（transcription），則能讓學習者自己找到錯誤，約七成的自我修正是對的。

## 2. 背景與脈絡

這個 repo 是 Scarlett 從零開始的日文學習日誌。到 2026-11-10 為止，課程已經涵蓋過去式（〜ました／〜かったです／〜でした）、比較與最高級（A より B の方が〜、一番〜）、變化（〜くなりました）、想做的事（〜たいです）、進行與狀態（〜ています）、て形接續、可能形（〜ことができます）、以及店員對話等主題。另外還有 `fukushuu` 複習系統，從 `data/vocab.json` 出單字題和「瞬間作文」題，用 Leitner 間隔排程。

也就是說，文法的「量」其實已經不少，日常話題（週末做了什麼、天氣、買東西、出去玩、家族）都有句型可以用。問題在於這些句型目前只在兩種情境出現過：讀課程頁時看懂，以及複習時從中文翻成日文。兩者都是「有時間想」的情境，跟自由會話需要的「即時聽懂、即時組句」差很多。

## 3. 研究問題與發現過程

最初的請求是「怎麼順暢的會話，參考語言學習的方式，用 Native Camp 十分鐘自由會話做口語訓練，因為文法學了但用不出來」。釐清之後，問題收斂成：

| 項目 | 內容 |
|------|------|
| 卡住的地方 | ① 聽不懂老師問什麼 ② 知道想說什麼但組不出句子 |
| 上課頻率 | 每天一堂，課前會準備一點 |
| 時間預算 | 課前、課後各十到十五分鐘 |
| 想接回 repo 的方式 | 課前準備頁、講不出來的句子進複習題庫（先只做研究文件） |

所以這份研究要回答的是：**在每天十分鐘會話、前後各十五分鐘以內的條件下，什麼樣的練習流程最能同時改善「聽懂問題」和「即時組句」？**

## 4. 技術分析：為什麼學了講不出來

### 4.1 現況：這個 repo 的練習偏重「看懂」與「有時間想」

目前的課程頁照「先講情境、再展開句型、最後小測驗」的結構寫，小測驗和 `fukushuu` 的瞬間作文都是看中文、寫或講出日文，沒有時間壓力，也沒有「先聽懂對方再回答」這一步。這是建立文法理解很好的方式，但它練到的是：

- 從中文出發翻成日文（單向）
- 一次一句、可以停下來想
- 題目是自己課裡的句子，不會出現沒學過的字

自由會話剛好相反：從聽日文出發、要連續回應、對方會用沒學過的字。

### 4.2 問題根源

**組不出句子：知識還停在「要想才拿得出來」的階段。** DeKeyser 的技能習得理論把學習分成三段：先有規則知識（陳述性），再透過練習讓行為開始改變，最後才是「流暢、自發、幾乎不費力」的表現。練習在這裡被定義成「有系統、有目的、為了發展知識而做的活動」。DeKeyser 也特別說，規則知識不是直接「轉換」成程序性知識，而是它提供了起點，真正讓人講得快的是反覆提取。換句話說，課程頁已經給了起點，缺的是「同一批句型反覆從嘴巴出來」的次數。

**聽不懂問題：聽力是由下而上的解碼加上由上而下的猜測。** 一篇研究初級日語學習者講電話的論文指出，聽力是 SLA 裡被研究得比較少的一塊，比較有效的是「由下而上的解碼能力」加上「推測這類補償策略」一起用。對初學者來說，老師的問題如果能事先猜到大概會是什麼（いつ・どこで・だれと・どうでしたか），由上而下那一半就先補起來了。

**另一個常被忽略的原因：卡住時沒有「求救的話」可以用。** 溝通策略的研究把「請對方澄清、確認意思、重複對方的話」列為學習者繞過語言缺口的正式工具，而且這些策略母語者自己也在用，不算丟臉。有研究發現，事先教過提問策略的學習者，之後在對話中確實會改用這些策略。初學者聽不懂時常常只能沉默，十分鐘就這樣流掉了。

### 4.3 研究上有支持的做法

**事前規劃（pre-task planning）。** Nielson（2012）比較了有引導和沒引導的事前規劃：有人告訴你「注意文法」的規劃會讓人比較準確、但句子變簡單；自己自由規劃則比較能提升流暢度。對 Scarlett 來說，課前準備的重點應該放在「想好要講什麼內容」，而不是把每句文法檢查到完美。

**重複同一個任務（task repetition）。** 多篇研究顯示重複講同一個話題能提升流暢度和用字，常跟事前規劃、課後轉寫一起使用；但效果在重複幾次之後會趨緩。Nielson 也發現工作記憶比較小的學習者，從重複中得到的流暢度進步更明顯。這支持「同一個話題連講兩三堂，再換下一個」。

**4/3/2 技巧。** Nation 設計的練習：同一段內容先講四分鐘，再用三分鐘、兩分鐘重講。早期研究發現第三次的語速比較快、停頓比較少。但後續有人質疑：進步可能只停在這個活動裡面，時間壓力也可能讓準確度和複雜度下降。所以這招適合拿來在課前「熱嘴巴」，不要期待它單獨帶來長期效果。

**整塊說法（formulaic sequences）。** Wood 的研究主張，流暢的即時口說靠的是一批「被當成一個字來處理」的多字串，他追蹤一位日本學習者接受專門教學後，這類說法用得越多、講得越流暢。也有學者指出這類研究樣本小、定義還有爭議。實際應用上的意思是：與其每次從單字和規則組句，不如把常用的句型框架整塊背起來，例如：

- 〜に行（い）きました。 *~ni ikimashita.*（去了〜。）
- 〜はどうでしたか。 *~wa dō deshita ka.*（〜怎麼樣？）← 老師最常問的
- とても〜かったです。 *Totemo ~katta desu.*（非常〜。）
- 〜たいです。 *~tai desu.*（想要〜。）

**輸出與「發現落差」。** Swain 的輸出假說指出，自己試著講出來，會讓學習者意識到「想說的」跟「說得出來的」之間的落差，這個落差就是下一步要學的東西。不過也有研究得到混合結果，所以落差本身要搭配後續的輸入（例如老師給的正確說法）才有用。這正好對應 Scarlett 想要的「講不出來的句子進複習題庫」。

**課後轉寫自己的錄音（post-task transcription）。** Lynch（2001）讓學習者把自己錄下來的對話寫成文字，學習者因此注意到自己的錯誤，並且反思形式和意思；有摘要提到學生自己改的地方約 72% 是對的，改的數量還比老師多。後續研究也發現持續這樣做，準確度會慢慢提升。

**跟讀（shadowing）。** 門田修平的理論認為跟讀訓練的是「由下而上」的聽力處理，濱田陽等人的課堂研究也支持它能改善這部分。限制是大多數研究在日本做、對象是學英文的人。這可以補「聽不懂老師」的那一半，而且這個 repo 的 `local/shadowing.html` 已經有跟讀頁可以用。

## 5. 解決方案探索與評估

### 方案 A：只靠多上課

每天上課本身就是輸出練習，什麼都不改也會慢慢進步。但研究顯示沒有規劃、沒有回顧的輸出，落差很容易講過就忘，而且「聽不懂就沉默」的情況會一直重複。

- **實作複雜度：** 無
- **維護影響：** 無
- **風險等級：** 中，進步慢，容易挫折

### 方案 B：課前、課中、課後三段式流程（推薦）

把上面的研究組成一套固定流程，用滿前後各十五分鐘的預算。核心是「同一話題講三堂、課前準備內容和老師可能問的問題、課中用求救句、課後把講不出來的句子收進複習」。

- **實作複雜度：** 低，一開始用紙筆或手機備忘錄就能做
- **維護影響：** 低，之後可以慢慢做成頁面與題庫
- **風險等級：** 低，每一步都有研究支持，最不確定的是 4/3/2 的長期效果

### 方案 C：先在 Claude Code 裡模擬會話，再上 Native Camp

先跟 Claude 用日文練一輪，再去上真人課。好處是可以無限重來，壞處是課前時間會超過十五分鐘，而且打字不等於開口講。比較適合當作週末加練，不適合每天的固定流程。

- **實作複雜度：** 中
- **維護影響：** 中
- **風險等級：** 中，容易變成「準備得很完美，但沒有練到即時反應」

## 6. 建議與決策指引

建議採用方案 B。它直接對應兩個卡住的地方：「組不出句子」靠事前規劃、整塊說法和重複同一話題；「聽不懂」靠預測問題、求救句和跟讀。時間也剛好落在前後各十到十五分鐘。

### 6.1 每天的流程

**課前（十到十五分鐘）**

1. **選話題**（一分鐘）：從最近一兩課的文法挑一個生活話題。例如剛學完過去式，話題就是「週末做了什麼」。**同一個話題連講三堂再換。**
2. **寫三句話＋一個反問**（五分鐘）：用中文想內容，再寫成日文。重點是內容，不用把文法檢查到完美。最後加一個可以反問老師的問題，讓對話接得下去。
   - 週末（しゅうまつ）に山（やま）に登（のぼ）りました。 *Shūmatsu ni yama ni noborimashita.*（週末去爬山了。）
   - とても寒（さむ）かったです。 *Totemo samukatta desu.*（非常冷。）
   - 来週（らいしゅう）はカフェに行（い）きたいです。 *Raishū wa kafe ni ikitai desu.*（下週想去咖啡廳。）
   - 先生（せんせい）は週末（しゅうまつ）何（なに）をしましたか。 *Sensei wa shūmatsu nani o shimashita ka.*（老師週末做了什麼？）
3. **猜老師會問什麼**（三分鐘）：針對這個話題寫下三到四個可能的問題，並且大聲唸。老師追問幾乎都是這幾種：
   - だれと行（い）きましたか。 *Dare to ikimashita ka.*（跟誰去？）
   - どうでしたか。 *Dō deshita ka.*（怎麼樣？）
   - どこにありますか。 *Doko ni arimasu ka.*（在哪裡？）
   - どうしてですか。 *Dōshite desu ka.*（為什麼？）
4. **不看稿講三次**（三分鐘）：把這幾句連起來講，第一次一分半、第二次一分鐘、第三次四十五秒（縮小版的 4/3/2），只為了讓嘴巴熱起來。

**課中（十分鐘）**

1. **開場先講需求**：
   - 初心者（しょしんしゃ）です。ゆっくり話（はな）してください。 *Shoshinsha desu. Yukkuri hanashite kudasai.*（我是初學者，請講慢一點。）
   - 間違（まちが）いはチャットに書（か）いてください。 *Machigai wa chatto ni kaite kudasai.*（我講錯的地方請打在聊天室。）
2. **聽不懂時用求救句，不要沉默**：
   - もう一度（いちど）お願（ねが）いします。 *Mō ichido onegai shimasu.*（請再說一次。）
   - 〜って何（なん）ですか。 *~tte nan desu ka.*（〜是什麼？）
   - 〜ということですか。 *~to iu koto desu ka.*（意思是〜嗎？）
   - 聽到關鍵字就**重複那個字**再加「？」，例如「山（やま）？」*Yama?*，老師就會換個說法。
3. **組不出句子時，先講短的**：先丟單字或最短的句子，例如「山（やま）、寒（さむ）かったです」，老師通常會幫你補完整，這就是下一步要記的句子。
4. **錄音**：用手機錄下整堂課（先跟老師說一聲比較禮貌）：録音（ろくおん）してもいいですか。 *Rokuon shite mo ii desu ka.*（可以錄音嗎？）

**課後（十到十五分鐘）**

1. **存聊天室紀錄**：把老師打的修正複製下來。
2. **聽錄音、轉寫一分鐘**（五分鐘）：挑自己講最多的那一分鐘，把自己說的話寫下來，再自己改一次。
3. **挑出三句「講不出來的句子」**（五分鐘）：包含想講沒講出來的、講錯被老師改的、聽不懂的問題。每一句寫成「中文意思＋正確日文＋羅馬拼音」。
4. **跟讀老師的修正句**（三分鐘）：照著錄音裡老師的說法跟讀幾次。

### 6.2 一週的節奏

| 天 | 做什麼 |
|------|------|
| 第一到三堂 | 同一個話題，每堂都換老師或同一位老師都可以，目標是一次比一次少卡住 |
| 第四堂起 | 換下一個話題，從最近學的文法選 |
| 每天的「講不出來的句子」 | 隔天進入複習，下一次換到同話題時特別拿出來用 |

### 6.3 風險與注意事項

- **4/3/2 的長期效果有爭議**，課前那三次只當作熱身，不要花更多時間在這裡。
- **重複同一個話題的效果大約三次後趨緩**，不要一個話題講一整週。
- **課前準備不要變成背稿**：研究顯示有引導、注重準確的規劃會讓句子變簡單，準備時想「內容」就好。
- **Native Camp 日文課的具體規則**（是否允許錄音、聊天室功能等）這次沒有查到官方資料，實際操作前要確認。官方的 Topic Talk 教材說明有提到「錯了也沒關係，想到的單字、句子、意見都可以跟老師說」，這跟上面的流程方向一致。

## 7. 下一步行動計畫

第一階段先用紙筆或手機備忘錄照流程跑一到兩週，確認每天前後十五分鐘做得到；第二階段再把有效的部分做進這個 repo。

- **立即行動：** 從明天的課開始，選「週末做了什麼」當第一個話題，照 6.1 的流程跑三堂。
- **中期目標一：課前準備頁。** 在 `resources.html` 的會話區（`<section class="kaiwa">`）加一頁，內容是固定的開場句、求救句、老師常見問題、以及「三句話＋一個反問」的準備表。這頁需要的設計決定不多，可以直接做，不一定要先寫 PRD。
- **中期目標二：講不出來的句子進複習題庫。** 目前 `fukushuu` 的題庫只讀 `data/vocab.json`（從課程頁產生），沒有地方放「會話課後的句子」。比較乾淨的做法是在私人的 `local/` repo 加一份會話句子檔（例如 `local/kaiwa/*.json`），讓 `review.mjs` 一起讀進瞬間作文。這牽涉到資料格式、要不要生音檔、句子要不要經過校對，**建議先寫 PRD** 再做。
- **額外調研：** Native Camp 日文課是否能錄音、是否有聊天室修正功能，需要看官方 FAQ 或直接在課堂上確認。
